# Frontend Data Display & UI Overview

This document outlines the current data, attribute sets, and UI components used in the web frontend to display extracted information, analytics, and recognized patterns. This is intended to serve as a reference for planning the mobile app and updated web interfaces.

## 1. Extracted Data & Attributes Displayed
The frontend retrieves the extraction payload and categorizes it into clear sections. These are primarily displayed as **Interactive Data Tables** built using the `AgGridReact` library (see `InteractiveDataTable.jsx`). 

The core categories of extracted data displayed include:
*   **Income Statement:** Revenue, expenses, and net profit/loss.
*   **Balance Sheet (Financial Position):** Assets, liabilities, and equity.
*   **Cash Flow:** Operating, investing, and financing data.
*   **Comprehensive Income (OCI):** Profit or loss plus OCI items.
*   **Changes in Equity:** Share capital, reserves, and retained earnings.
*   **Auditor's Report:** Audit opinions and key matters.
*   **Future Outlook:** Forward-looking statements and growth expectations.
*   **Corporate Governance:** Board details, frameworks, and compliance clauses.
*   **ESG Report:** Environmental, social, and governance disclosures.
*   **Shareholding Information:** Ownership structure and major shareholders.
*   **Notes:** Supporting financial notes and policies.
*   **Subsidiaries:** Group structure and entity info.
*   **About the Company:** General profile and business model.

### How it is displayed:
*   **Tabular Format:** Extracted sections with tabular data are rendered into sortable, filterable, and resizable grids.
*   **Value Formatting:** Financial figures dynamically format scaling indicators (e.g., '000s) automatically and apply localized currency definitions, percentages, and decimals for ratios.

## 2. Analytics, Ratios, and Financial Metrics
The legacy analytics engine (e.g. `AnalyticsCards.jsx`) digests raw ratios, metrics, and forensic flags generated by the backend (`ratio_engine.py`, `risk_engine.py`, `confidence_score.py`). 

### Core Ratio Formulas & Calculations Built into the System:

**1. Growth Metrics (YoY & CAGR)**
*   **YoY Growth** (Revenue, Net Profit, Operating Profit, EPS, Assets, Equity): `(Value_t - Value_t-1) / abs(Value_t-1)`
  * *Guardrail*: Nullified if growth falls outside `[-0.50, 1.50]` (-50% to +150%).
*   **CAGR-like Growth**: `((Last Value / First Value)^(1/periods)) - 1`

**2. Profitability and Return Ratios**
*   **Gross Margin:** `Gross Profit / Revenue`
*   **EBITDA Margin:** `EBITDA / Revenue`
*   **Operating Margin:** `Operating Profit / Revenue`
*   **Net Margin:** `Net Profit / Revenue`
*   **ROA (Return on Assets):** `Net Profit / avg(Assets_t, Assets_t-1)` (Falls back to Current Assets)
*   **ROE (Return on Equity):** `Net Profit / avg(Equity_t, Equity_t-1)` (Falls back to Current Equity)
  * *Guardrail*: Nullified if falling outside `[-0.50, 0.60]`.
*   **ROCE:** `Operating Profit / (Assets - Current Liabilities)`

**3. Liquidity and Solvency**
*   **Current Ratio:** `Current Assets / Current Liabilities`
*   **Quick Ratio:** `(Current Assets - Inventory) / Current Liabilities`
*   **Cash Ratio:** `Cash / Current Liabilities`
*   **Debt to Equity:** `Debt / Equity` (Falls back to total liabilities if debt is missing)
  * *Guardrail*: Nullified if falling outside `[0.0, 10.0]`.
*   **Interest Coverage:** `Operating Profit / Interest Expense`

**4. Efficiency & Working Capital**
*   **Asset Turnover:** `Revenue / Assets`
*   **Inventory Turnover:** `Cost of Revenue / Inventory`
*   **Inventory Days:** `365 / Inventory Turnover`
*   **Receivable Days:** `(Receivables / Revenue) * 365`
*   **Payable Days:** `(Payables / Cost of Revenue) * 365`
*   **Cash Conversion Cycle:** `Receivable Days + Inventory Days - Payable Days`

**5. Cash Quality and Shareholder Metrics**
*   **Free Cash Flow (FCF):** `Operating Cash Flow - Capex Proxy`
*   **Cash Conversion Quality Score:** `clamp((Operating Cash Flow / Net Profit), 0..1.5) / 1.5`
*   **Earnings Yield:** `EPS / Stock Price`
*   **Dividend Payout Ratio:** `Dividends Paid / Net Profit`

### System Scoring Models:
**Risk Score Model (0-100 scale, translated into Low, Moderate, High bands):**
The `risk_engine.py` builds an overall score utilizing strict threshold gating (`Critical` vs `Warning` parameters).
*   **Profitability Score (Weight: 20%):** Warning = 0.06 | Critical = 0.00
*   **Liquidity Score (Weight: 15%):** Warning = 1.2 | Critical = 1.0 (Low is risky)
*   **Debt Risk (Weight: 20%):** Warning = 1.5 | Critical = 2.5 (High is risky)
*   **Cashflow Health (Weight: 20%):** Warning = 0.8 | Critical = 0.4
*   **Growth Stability (Weight: 15%):** Warning = 0.02 | Critical = -0.05
*   **Accounting Red Flags (Weight: 10%):** Sums severity of forensic flags.

**Data Reliability & Confidence Scoring:**
Base calculation starts from a pool that assigns points for component completion:
*   `Confidence Score` applies weighted checks: Completeness (+0.20), Validation Pass Rate (+0.20), Unit Consistency (+0.15), Target Year Coverage (+0.15), etc., subtracting penalties `- min(issue_count * 0.04, 0.30)`.
*   *Hard Gates Block Analysis:* If basic balances (Assets != Liabilities + Equity) drift `> 3%`, all advanced graphing and confident scoring logic is forced into Restricted Mode (capping score `<0.25`).

### How it is displayed (UI & Graphs):
*   **Time-Series Layout (By Year):** The analytics and ratios are fundamentally presented strictly **by year**. The framework iterates through historical years (e.g., `["2025", "2024", "2023"]`), mapping out column rows to compare metrics, values, and flags side-by-side annually (via the `by_year` object). 
*   **Metric Info Cards:** Standalone layout blocks showing single data points conditionally formatted based on rules. 
*   **Graphs / Charts (The Profitability Radar Chart):** 
    The only true graphic plotting implemented natively is a **Profitability Radar Chart** utilized to display relative profitability metrics. Instead of an external charting library like Chart.js or Recharts, the radar chart is rendered manually using inline declarative `SVG` elements. 
    *   **Implementation:** It executes polar mathematical formulas natively inside `AnalyticsCards.jsx`.
    *   **Trigonometry:** It sets a predefined `radius`, maps out angles dynamically using `-Math.PI / 2 + index * angleStep`, calculates vertex vectors via `Math.cos(angle) * r` / `Math.sin(angle) * r`, and connects the axes (`axes.map`) using a unified drawn `<polygon>` shape plotted over grid lines.

## 3. Pattern Recognition Display
Insights generated by backend pattern rules are received through the `analytics.patterns` payload.

### Are there tables or graphs for the patterns?
**No**, patterns are not currently displayed as plotting charts or dense data tables. Instead, the frontend renders patterns via a specialized dashboard widget called the **Pattern Detector Matrix**.

**Pattern Detector Matrix (Card Grid System):**
Extracted patterns map sequentially to a responsive CSS grid of structural "Cards" detailing specific pattern aspects:
*   **Title/Name:** The pattern name.
*   **Status Indicators:** A visual badge chip dictating status—colored red (indicating **"detected"**) or green (indicating **"clear"**).
*   **Meaning:** A descriptive sub-text summarizing what the pattern implies.
*   **Confidence Score:** A percentage indicator derived from the analyzer's probability metrics.
